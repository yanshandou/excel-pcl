# Excel Inspector

本机运行的 Excel 检查工具：HTML / JavaScript + Python + openpyxl。不需要安装 Excel，不修改原文件，不向外部服务发送工作簿。

## Windows 启动

安装 Python 3.10 或更新版本，解压后双击 `start.bat`。首次运行需要联网安装 openpyxl，随后会打开 http://127.0.0.1:8765 。命令行窗口需保持打开；关闭窗口或 Ctrl+C 停止服务。

使用 Git Bash（或 macOS / Linux 终端）时，可改为运行 `./start.sh`，例如 `./start.sh --port 9000`。

也可手动运行：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

端口冲突时：`python app.py --port 8766`。

## 新旧模板版本差异审查

1. 在页面顶部将文件分别拖入“上一版（参考模板）”和“这一版（修改后的模板）”区域，或点击区域选择文件，然后点击“比较两个版本”。每个区域只接受一个不超过 30 MB 的 .xlsx / .xlsm 文件。
2. 查看差异总览：内容变化、格式差异、位置变化、需确认条目及未配对工作表。各项可能重叠。
3. 点击工作表总览行，按需筛选格式变化、内容变化、位置变化或需确认条目，并搜索、翻页。
4. 明细并排列出新旧地址、内容、格式属性变化和匹配依据。点击“上一版 / 这一版”可定位到下方原有七项检查。
5. 工作表改名且内容相同时会建议配对；不能自动配对时，可展开手工配对区，指定新旧工作表并重新比较。
6. 可导出差异 JSON；原有完整检查 JSON 导出也保留。刷新页面会清空结果。

比较在本机完成，两个文件都不修改。`/api/compare` 返回差异以及两个版本的七项检查数据，单文件检查接口仍然保留。

### 对应关系与审查边界

- 同名工作表优先对应；改名工作表仅在非空内容和坐标完全相同且唯一时建议对应。人工配对优先。
- 单元格按唯一内容、行列内容序列和相等长度区段的顺序尝试对应，因此能够处理部分插删行列与移动场景。顺序推测和歧义需人工确认。
- 重复内容、大幅改版、同时增删且修改内容可能无法可靠对应，显示“新增或未匹配 / 删除或未匹配”，不宣称一定新增或删除。
- 新增或未匹配的内容仅建议参考老版同列、同数据类型的邻近单元格。建议参考不是正式格式规范，仍需人工确认。
- 比较内容及原七项相关属性，包含字体、字号、粗体、字体颜色、斜体、下划线、删除线、对齐、文字旋转、缩进、换行、缩小、数字格式、合并尺寸。
- 打印范围、可见性和最大行列变化单独列出；图形、边框、填充色、行高列宽、条件格式和宏不参与版本比较。主题颜色与继承样式限制沿用原检查器，公式不重算。
- 差异不等于不合格；工具不会将“未发现差异”表述为符合全部业务要求。

## 原有七项检查

1. 选择多个文件，或选择文件夹（包含子文件夹）。后一次选择替换前一次选择。
2. 填写目标字体和字号，点击开始检查。每个文件单独处理，失败文件不会中断后续文件。检查期间固定本批次文件、字体和字号；点击取消检查会在当前文件处理完后停止，保留已完成结果。
3. 选择文件和工作表，切换七项规则；搜索、仅看有颜色、点击单元格查看属性。
4. 可切换当前页网格，或导出完整 JSON。导出数据可能包含原文件内容。

默认字体是建议值，原 VBA 从操作表读取字体、字号，源码没有固定值；请按原工具配置调整。

## 已实现与差异

- 七种分类的优先级按 `reference/original.vba` 移植；蓝色不一定异常，红色也不一定异常。
- 字体：字号匹配标蓝；字体不匹配覆盖为红；粗体/非黑色显示网纹。
- 格式：仅 `0_`、`#,##0_`、`0.0_` 标绿，其他非标准/文本格式标黄；没有自行扩大数字格式范围。
- 垂直 distributed 按代码标蓝，虽然 VBA 说明文字称“其他红”。
- 提取文档标题、工作表、打印范围、名称定义及 DrawingML 图形名称。图形按 XML 部件列出，暂未映射回工作表；VML/ActiveX/嵌入对象等没有完整覆盖。
- 打印范围外依照 VBA 只比较已用区域的右下角；不检查左/上边界，多区域为“不明”。这是原规则限制，不代表严格的内容越界检测。
- 稀疏扫描有数据或样式的单元格，不铺满整个 UsedRange，也不额外生成外围 10 行/列的空单元格。Excel COM 的 UsedRange、继承样式、合并区从属格与 openpyxl 可能不同。
- 预览不复刻 Excel 的列宽行高、边框、原背景或图形；保留合并区域信息，网格仅展示当前页。
- NumberFormatLocal 在 openpyxl 中没有等价接口，使用 OOXML number_format。公式不重算，条件格式不计算；主题颜色识别是近似。
- 最大单文件 30 MB，解压后总计 150 MB，每表已存储单元格 250000 个，合并区域合计覆盖不超过 250000 个单元格。加载前会预检工作表 XML，后端也校验单文件 30 MB 限制。一次仅处理一个文件，结果保存在浏览器内存，刷新清空；大批次需分批。
- 原文件缺少真实测试样本，因此尚未证明与 Excel 原工具逐项等价。

## 验证

```bash
python -B -m unittest -v
node test_frontend.cjs
```

测试覆盖规则优先级、换行优先、合并、公式、格式分类、打印边界、无打印区域、多打印区域，以及无效参数、文件大小、加载前单元格与合并区域限制和跨行合并区域查找。此版本还未完成真实 Windows 浏览器人工验收。

## 代码结构

- `web/index.html`：页面结构。
- `web/css/styles.css`：页面样式和响应式布局。
- `web/js/comparison.js`：版本比较、总览、筛选、工作表配对和明细定位。
- `comparison.py`：新旧版本工作表及单元格匹配、格式差异和审查提示。
- `web/js/app.js`：文件选择、检查批次、搜索、结果展示和导出交互。
- `app.py`：本机 HTTP 服务、公开静态资源路由和检查 API。
- `inspector.py`：Excel 文件预检、属性提取和七项检查规则。
- `test_inspector.py`：检查逻辑测试。
- `test_comparison.py`、`test_app.py`：版本比较及 API 回归测试。
- `test_frontend.cjs`：无需浏览器依赖的前端流程测试（需要 Node.js，仅测试使用）。

前端不需要构建步骤。请通过启动脚本访问本机服务，直接双击 HTML 无法调用 Python 检查接口。
